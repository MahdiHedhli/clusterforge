# Instructor guide: 200/300 scenarios

**Instructor material.** Do not include this file in a learner's independent-assessment or tutoring-agent context. Its public location is not an access-control mechanism.

**Status:** Draft scenarios; runtime not verified. Validate each chosen variant on the intended environment before assessing a learner. Do not introduce an untested fault into a shared or production system.

## Delivery protocol

Read the [learning contract](../docs/learning-contract.md) and [practical setup](../curriculum/practicals/levels-200-300/README.md). Verify the exact target, ownership, baseline, recovery path and scope. Record the resource identity and original field before mutation. Use the explicit `k` wrapper defined in the practical, which supplies kubeconfig/context/namespace but is not a sandbox.

Choose one fault for guided practice and a different verified variant for assessment. Deliver only the symptom and approved boundaries. For multi-fault assessments, validate interaction and recovery ordering first. Do not choose a fault whose only repair requires unauthorized cluster changes.

## Namespaced fault variants

All commands below mutate only the named synthetic fixture after setup and authorization. They are not learner answer prompts.

### Release cannot start

After confirming the baseline image works, change only the image to an intentionally invalid reference:

```bash
k set image deployment/cf-web web=busybox:cf-intentionally-invalid
```

Expected investigation: new ReplicaSet, image-pull event, absent application logs for the failed container, old/new revision distinction. Restore the recorded original image, wait for rollout, and retest the Service. Verify the invalid tag genuinely fails in the target registry before using it as an assessment fixture.

### Pods are running but unavailable

Change the Service selector:

```bash
k patch service cf-web --type=merge -p '{"spec":{"selector":{"app":"cf-no-backend"}}}'
```

Expected investigation: no selected ready backends despite healthy application Pods. Restore the recorded selector and verify EndpointSlices plus client requests. Never use an established port-forward as the success criterion.

### Selected backend on the wrong port

```bash
k patch service cf-web --type=json -p '[{"op":"replace","path":"/spec/ports/0/targetPort","value":8081}]'
```

Expected investigation: selected endpoints, working direct backend port, failing Service path. Restore targetPort to its recorded value and retest both clients before any policy test.

### Unsatisfiable placement

```bash
k patch deployment cf-web --type=merge -p '{"spec":{"template":{"spec":{"nodeSelector":{"clusterforge.invalid/placement":"never"}}}}}'
```

Verify no node has that label/value. Expected investigation: FailedScheduling and the unsatisfied Pod constraint, not a node outage. Remove only the injected selector key or restore the entire original nodeSelector value. Do not relabel nodes or remove taints to repair this fixture.

### Bad readiness target

```bash
k patch deployment cf-web --type=json -p '[{"op":"replace","path":"/spec/template/spec/containers/0/readinessProbe/tcpSocket/port","value":8081}]'
```

Expected investigation: a running process, failing readiness, unavailable backends and unchanged restart behavior attributable to readiness alone. Restore the recorded probe, then test application behavior. Do not teach disabling the probe as the solution.

### Reader binding defect

In the synthetic `cf-reader` RoleBinding, replace the subject name with `cf-nobody`, preserving the original subject record. Use a reviewed local manifest with the fixed lab namespace and apply through `k`. Expected investigation: task and Role are correct but the binding targets the wrong identity. Restore the original subject and retest both required and forbidden operations.

### Network policy mismatch

After proving the supplied ingress policy works, change its allowed peer label to an unused value using a reviewed local manifest. Expected investigation: correct backend health, changed allowed set and a legitimate client denied. Restore the peer selector rather than adding an allow-all policy. Verify no overlapping policy makes the intended negative test meaningless.

## Analytical packet notes

The identity packet is descriptive JSON, not a signed token. Expected observations include a wrong audience in one descriptor and incomplete evidence that offboarding invalidated an earlier credential. Do not grade the packet as live OIDC, SCIM or federation validation.

The incident packet shows a successful ConfigMap read, a denied Secret read, an exec API request, a benign-looking process event and later binding removal. It does not establish data exfiltration, identify who possessed the workload credential, or prove that binding removal revoked an already issued token. The recorded network-telemetry gap must remain an unknown.

For the incident inject, reveal that the exec may have been approved debugging or that the identity is shared. Reward a revised hypothesis and proportionate response, not commitment to the first attacker narrative.

## Architecture and customer injects

Use the fictional customer requirements, never an employer's private outline. After the first design, introduce one change: contractors need temporary diagnostics; external artifact access becomes necessary; the audit sink is unavailable; the workload moves from dedicated GPUs to a sharing mode; or the recovery objective tightens.

Require the learner to revise the affected requirements, threats, controls and evidence requests. Do not demand an unsupported silicon-level or legal assurance from a namespace lab.

## Recovery and scoring

Restore original fields explicitly. Reapplying the baseline does not guarantee removal of every imperatively added field. Verify cleanup, functional requests and any intended baseline policy behavior before ending the exercise. Preserve raw evidence privately and score using the [common rubric](../assessments/README.md).

Record instructor fault validation separately from learner competency. A successful rehearsal by an agent is not evidence that a learner independently solved the incident.
