# K8S-300 practical: Harden without breaking the service

**Status:** Draft assessment; runtime not verified. **Suggested duration:** three 45-minute blocks.

## Prerequisites

K8S-300 lessons or equivalent evidence, a verified dedicated lab, approved admission enforcement, network-policy enforcement and a defined audit/runtime evidence path. Missing capabilities block the corresponding implementation gate. Use the [common rubric](README.md).

## Customer brief

A team must run a web workload that accepts requests only from its approved client, does not need Kubernetes API credentials, and must remain observable during investigation. A proposed deployment contains unnecessary permissions and one configuration defect. Make the workload functional and appropriately constrained. Preserve one legitimate diagnostic path.

## Required work

Inspect before changing anything. Identify identities, data access, privilege, network paths and missing telemetry. Rank the findings by the attack path they enable rather than by scanner severity alone. Propose and apply only approved namespaced corrections.

Demonstrate a successful application request and a deliberately disallowed request. Show the workload's intended identity and effective privilege. Validate rejection of an unsafe candidate through approved admission tests without deploying a host-compromising workload. Trace a benign diagnostic action through the configured evidence path.

Explain artifact provenance, secret handling, rollback and residual risks. Do not broaden access to get a green health check. No container escape, real credential extraction, cloud metadata probing or cluster-wide policy change is authorized.

## Passing evidence

Provide a before/after control matrix with positive and negative observations, an attack-path explanation, the telemetry record, and a concise handoff. The instructor selects an unseen compatible variant from the [instructor guide](../instructors/levels-200-300.md).

Apply the common rubric. Distinguish live-control qualification from tabletop analysis. If a required sensor or admission mechanism is unavailable, record the gap and complete only the qualified portions; do not award the full implementation gate.

## Cleanup and progression

Restore the approved baseline and remove only assessment-owned resources or policies. Record the exact SEC-300 prerequisite still missing, if any. Preserve company-specific evidence internally and share only a synthetic or sanitized learning summary publicly.
