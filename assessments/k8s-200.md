# K8S-200 practical: The unsuccessful release

**Status:** Draft assessment; runtime not verified. **Suggested duration:** three 30-minute blocks, with a recorded safe checkpoint between blocks.

## Prerequisites

K8S-200 lessons or equivalent evidence, a healthy dedicated lab, and an instructor who can select an unseen variant. Read the [common rubric](README.md). Do not expose instructor fault notes to the learner or tutoring agent during the attempt.

## Customer brief

A small service was updated. Some Pods appear healthy, but clients cannot reliably use the application. The team also reports that one replacement workload will not become ready. Restore the service without granting additional privileges, deleting persistent data or rebuilding the cluster.

The instructor supplies the affected namespace, desired application behavior, approved change boundary and a verified starting symptom. The learner is not given the root cause. Use only synthetic workloads and data.

## Required work

1. Establish scope and capture the initial state before mutation.
2. Form and test at least two plausible hypotheses.
3. Trace the rollout, placement/readiness and actual client-to-Service path.
4. Repair the smallest justified set of fields. Correct the source configuration as well as live state where appropriate.
5. Repeat the original request and test a second relevant condition.
6. Deliver a two-minute customer briefing and a safe handoff.

The instructor selects two compatible namespaced faults from the [instructor guide](../instructors/levels-200-300.md), verifies both before the assessment, and records their interactions privately. A guided rehearsal cannot count as the independent attempt.

## Passing evidence

Provide object identities, timestamps, decisive observations, before/after differences and verification results. Explain one tempting but unjustified fix you rejected. Include storage implications even if the application is stateless: identify which recovery actions would become dangerous for a stateful workload.

Apply the common 100-point rubric. The operator gate does not award live control-plane build, upgrade, HA or etcd-restore credit. Record those as separate qualifications.

## Cleanup and next step

Return the fixture to its verified baseline, preserve sanitized evidence, and record the next unmet competency. A failed attempt becomes a targeted practice task, not a reason to repeat the entire track.
